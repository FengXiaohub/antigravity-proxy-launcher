正常登录与使用 Agent

在本机验证的版本中，Antigravity 后台没有跟随系统代理。 这两个非官方工具为它注入本地代理环境，并辅助安装已经下载好的官方更新包。

问题出在哪

Antigravity 的登录与 Agent 通道不在主界面进程里，而由独立后台进程负责： 

/Applications/Antigravity.app/Contents/Resources/bin/language_server

本机排查显示，这个 Go 后台通过环境变量使用代理；从官方图标启动时没有继承预期代理配置， 在受限网络下可能登录超时。代理启动器为它提供 HTTP_PROXY、HTTPS_PROXY 等变量。

这一结论适用于本机验证过的版本，不保证未来版本仍使用相同路径或网络机制。

表现：窗口能打开，但登不上、Agent 用不了。

为什么不用 TUN

适合需要保持规则模式和系统代理，或希望避免新增虚拟网卡的用户。本工具不启用 TUN，也不改全局网络配置。

TUN 的表现取决于客户端和配置。Mihomo 支持多种协议栈及路由排除项，不能概括为全部使用 gVisor 或无法排除路由。 参见 Mihomo 官方说明。

所以本项目的取舍是：不碰整机网络，只调整一个进程启动瞬间的环境变量。 影响面被压缩到 Antigravity 一个 App。

两个工具

Antigravity 代理启动

每次打开 Antigravity 时用

探测本地代理端口 → 验证真的能出网 → 注入环境变量 → execve 官方二进制。

agy update

右上角出现「重启更新」时用

校验已下载的包 → 正常退出 → 整包替换 → 复验 → 失败尝试恢复。最多保留一份旧版原件。

双击才工作，没有独立常驻服务；启动器最终由官方进程替代。

启动器是怎么做的

  1. 读 scutil --proxy，取出 HTTP / HTTPS / SOCKS 端点，且只接受本机回环地址
  2. 逐个 nc -z 探活——端口「开着」不代表「能用」
  3. 用 curl 请求 generate_204，必须真的拿到 204 才算通过
  4. 都不行则回退常见端口：7890 / 7891 / 7893 / 7897 / 1080 / 12000
  5. 检查「上次更新是否未完成」和「是否已有实例在跑」（只激活现有窗口，无法补注入代理；来源无法确认时弹窗说明）
  6. 注入 6 个代理变量 + 内网 NO_PROXY，然后 execve 官方二进制
为什么必须用 execve： macOS 上的 open --env KEY=VALUE 在部分版本（实测 27.x）不会把变量传进被启动的 App， 而父进程 execve 的环境继承是确定的。

安装

  1. 从 GitHub 的 Code → Download ZIP 下载并解压整个仓库。
  2. 双击 Install.command，终端窗口自动执行安装，结束后弹窗显示结果，无需输入命令。
  3. 结果显示成功后，使用自己 ~/Applications 中原来的两个图标。

需先安装官方 Antigravity，并有可运行的 Apple 命令行工具与 Python 3。首次运行可能需要先完成 Apple 的命令行工具安装提示。

安装器先构建、验证，再原位替换助手；失败会尝试恢复。只注册原来的两个助手，不创建第二份可运行的 Antigravity。安装也会写入用户级恢复记录。

当前实机验证范围为 macOS 27.2.1、Apple Silicon。本项目没有 Apple 开发者签名与公证，首次双击 Install.command 可能被 Gatekeeper 拦截：请右键「打开」，或到「系统设置 → 隐私与安全性」点「仍要打开」。不要执行 spctl --master-disable 关闭整机安全策略。更新时若需要「App 管理」权限，见 README 说明。

装了中文汉化补丁能用吗？

可以。已打静态汉化补丁（修改 app.asar / 本地重签名）的客户端无需先还原回英文，退出后直接双击 agy update 即可整包升级为最新 Google 官方签名版。

常见弹窗与处理

弹窗含义与处理
没有找到可用的本地代理没有探测到可用的本机代理端口，或系统代理未开启。先打开代理客户端（VPN 客户端），连接节点并开启「系统代理」（规则模式即可），再双击重试
本地代理端口有响应，但 Google 连接预检在等待上限内未成功端口通，但通过代理请求 Google generate_204 超时或没有返回预期结果；这不代表所有 Google 服务都不可用。先确认代理客户端已连接，稍后重试；持续失败再检查或更换节点
Antigravity 已经在运行，本次只能激活窗口现有进程无法确认由本启动器打开，启动器只能激活窗口，不能给它补上代理。若登录或连接失败，按 ⌘ Q 完全退出后再点代理启动器
Antigravity 已在运行，但窗口没有激活已有 Antigravity 进程，但启动器请求系统激活窗口失败。从 Dock 打开；若一直未响应，先正常退出再试
正在检查或安装更新「agy update」正在占用操作锁。等更新窗口结束后再打开
上次更新尚未完成发现未完成的更新记录（替换中途被打断）。先双击「agy update」恢复，再打开 Antigravity
没有找到可运行的 Antigravity主程序缺失或不可执行。先双击「agy update」检查是否需要恢复旧版
没有找到已下载的新更新包（agy update）本地没有已下载的更新包，不代表线上没有新版本。先让 Antigravity 检查并下载更新，再双击「agy update」

更新与换节点

  • 端口改变时，完全退出后用代理启动器重开。仅切换节点且端口不变，通常无需重启；连接可能短暂中断。
  • 等任务完成、正常退出后，手动双击 agy update。它会请求通过代理启动器重开；官方的 Reboot and Update 按钮没有接到本工具。

边界与安全

  • 不常驻：没有独立后台服务；更新恢复记录会保留在用户目录
  • 不改系统：不写系统代理、不改 DNS、不加开机自启、不动 /etc
  • 不改包内文件：更新时整包替换，不修改 app.asar；新安装的更新包强制要求 Google Team ID、完整签名及公证凭证，旧版备份以完整文件指纹校验
  • 保留官方身份：官方 bundle ID 不变；系统会注册两个辅助工具自己的图标。旧版恢复原件不注册为第二个官方 App
  • 不收集数据：无网络上报；日志在 ~/Library/Logs/AntigravityHelper.log，不含凭据
  • 卸载：先确认没有未完成更新，再删除两个助手。日志、恢复状态与一份旧版原件不会自动消失；清理路径见 README，勿删会话目录

非官方本地辅助工具，与 Google 无关。启动时注入代理，更新时整包替换。
